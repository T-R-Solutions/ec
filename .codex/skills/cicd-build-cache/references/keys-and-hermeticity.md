# Keys and hermeticity
Build cache keys must include all output-affecting inputs: source and lockfile content, compiler/toolchain version, target platform, action implementation, arguments and relevant environment. Prefer length-delimited canonical encoding over concatenation. A digest key is not an authorization credential. Untracked host tools, volatile inputs and nondeterministic output invalidate safe reuse. If hermeticity is not demonstrated, disable action-output caching and record the reason. Restore-key prefixes for dependency caches may be intentionally coarse but must remain within the same trust scope.
