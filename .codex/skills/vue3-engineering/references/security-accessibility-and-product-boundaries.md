# Security, accessibility and product responsibility boundaries

> Use the destination's existing requirements and evidence format; named workflow documents are examples, not prerequisites. Optional SDD mapping is configured outside this skill. Ec-specific rules below apply only to an Ec consumer whose current contract establishes them.

**Vue-specific secure rendering** (Vue official Security Guide [V18]): `{{ string }}` and attribute interpolation use escaping, but this does not make untrusted HTML, URLs, arbitrary Vue templates or script-bearing bindings safe. Never compile user input as a template. `v-html`/`innerHTML` on untrusted content is hazardous; if authorized rich HTML is a requirement, obtain explicit threat model, upstream sanitization and an appropriate security review. Treat backend-supplied links as untrusted until validated by policy; do not rely on a client sanitizer as the sole defense. CSP and server-side authorization belong to broader security owners.

**Component accessibility interface:** prefer native semantic controls, named buttons, valid labels, status text, visible focus and keyboard access. Keep loading/error messages discoverable. Guard conditional re-renders from dropping focus. A Vue component author may consult `web-accessibility` when available and a concrete question remains for WCAG 2.2 AA checks and assistive technology tests, and with `design-system` for tokens and patterns. A screenshot, a successful TypeScript compilation, or a custom static checker does **not** certify WCAG compliance.

**Generic skill / Ec intersection:** if the target is Ec, locate and read the applicable product and interface requirements in the consumer before relying on Ec-specific examples. The Ec norms own product naming, navigation, safe actions, YAML authority and Visual/Form/YAML parity. Vue components are projections/clients of real configuration and backend state; neither local `ref` nor `v-model` becomes configuration truth. Distinguish draft, published, effective and failed when current project workflow defines them. Never claim an administrator action completed on the basis of an emitted event alone.

**Not this skill:** YAML syntax/schema belongs to `ec-declarative-resource-schemas`; mode round-trip to `ec-semantic-configuration-projections`; publication to `ec-configuration-publication`; authorization to `ec-effective-permissions`; agent/run operations to their Ec skills; CSS tokens to design-system; complete WCAG acceptance to `web-accessibility`.

**Security tests to request:** suspicious user text rendered as text, not executable markup; unknown/hostile URLs rejected by trusted boundary; denied actions remain denied at server; no secrets leak into DOM/log; component-level stale/unauthorized UI state cannot be mistaken for a grant; accessible error/loading feedback validated by actual browser tests.
