# Peer-reviewed research: findings, scope, and limits

> Imported authoring record. Research dates, consultations and execution claims below belong to the supplied source package; they were not reproduced in this adaptation. Referenced validation scripts, fixtures, product norms and logs are not bundled unless present in this folder. Verify their availability and provenance before use. No historical PASS is current acceptance.

The publications below were located via journal/conference publisher pages, academic indices or author publication catalogs. DOI strings and venues were checked against those records. These findings are **not** performance measurements of this package or proof that any Ec authentication has been implemented.

1. **Fett, D.; Küsters, R.; Schmitz, G. (2016). “A Comprehensive Formal Security Analysis of OAuth 2.0.” ACM CCS, pp. 1204–1215.** DOI: https://doi.org/10.1145/2976749.2978385. Formal web model covering concurrent grant modes and authorization, authentication and session integrity under explicitly modeled countermeasures. **Supports:** identify cross-protocol and client/session-binding threats, formulate attack oracles. **Does not prove:** every OAuth client or deployment is secure, or a particular library is correct.
2. **Fett, D.; Küsters, R.; Schmitz, G. (2017). “The Web SSO Standard OpenID Connect: In-Depth Formal Security Analysis and Security Guidelines.” IEEE CSF, pp. 189–202.** DOI: https://doi.org/10.1109/CSF.2017.20. Formal security conditions for OIDC in a browser/web model, including previously identified and new attack variants. **Supports:** enforce issuer/session/nonce binding and define negative cases. **Limits:** proofs hold under their model assumptions and identified mitigations; are not blanket certification of implementations.
3. **Mainka, C.; Mladenov, V.; Schwenk, J. (2016). “Do Not Trust Me: Using Malicious IdPs for Analyzing and Attacking Single Sign-On.” IEEE EuroS&P, pp. 321–336.** DOI: https://doi.org/10.1109/EuroSP.2016.33. Empirical malicious-IdP attacks on OpenID implementations. **Supports:** adversarial-issuer and cross-account isolation test design. **Limits:** the studied population and protocol versions are historical; do not transfer attack prevalence numbers to current OIDC deployments.
4. **Mainka, C.; Mladenov, V.; Schwenk, J.; Wich, T. (2017). “SoK: Single Sign-On Security — An Evaluation of OpenID Connect.” IEEE EuroS&P.** DOI: https://doi.org/10.1109/EuroSP.2017.32. Examines SSO attack classes and OIDC-specific security issues including IdP confusion and malicious endpoints. **Supports:** explicit provider trust lists, discovery/SSRF oracles, separation of token context. **Limits:** applicability depends on extensions, versions, trust assumptions and deployed countermeasures.

The papers include formal reasoning and experimental vulnerability analysis, **not controlled trials of user-facing login performance**, nor empirical benchmarks of the Node fixture. The supporting peer-reviewed work does not change the authority of final protocol texts or the user's product policies. For current production protections, re-check RFC 9700, OIDC errata, library advisories and provider-specific implementation guidance.
