# Labels, categories, and information scent

**Information scent** is a conceptual cue about the likely value of following a link, discussed in information-foraging research. This does not imply that scent is an automatically calculable quality score for a project, or that one set of labels is universally optimal.

## Label review procedure

1. For each top-level label, record which tasks and resource kinds belong there; also record what **does not** belong there.
2. Elicit users' own words from observed tasks, queries and interviews. Capture aliases and terminology differences by role or locale.
3. Prefer nouns for stable resource categories and action verbs for tasks; use explicit context when terms overlap (e.g., configuration vs execution state, project vs workflow).
4. Test first-click/first-choice expectations and final task success separately. A correctly guessed first menu label is not proof the final record can be found.
5. Avoid unexplained acronyms and overloaded catch-all buckets such as "More", "Misc" or "Tools" when task evidence indicates confusion.
6. Keep repeated function names recognizably consistent and include the visible label in the accessible name when it applies.

## Negative cases

Ambiguous sibling labels; user action is under a category that implies another resource; synonym matching unexpectedly changes authorization scope; localized label becomes a canonical ID; stale saved bookmarks with an outdated label; a result title lacks context and cannot be disambiguated.

## Research limits

Pirolli and Card (1999) describe an information-foraging theoretical approach; the theory **does not specify** a single required UI structure or a measurable speedup from changing a menu label. Toms (1999) studied a specific academic website with 24 users, where findability problems were observed; it is not a transferable expected success rate. Schmettow and Sommer (2016) did not find a browsing-performance relationship predicted from card-sort congruence in municipal websites. This is a direct warning against claiming a structure is validated by card sorting alone.
