# Collection Pagination, Filtering, Sorting and Links

Do not pretend that a single cursor format is an HTTP standard. Define token opacity, signature/integrity where applicable, binding to tenant/auth principal and the filter/sort snapshot, TTL, error response, page limit, deterministic tie-breaking, cursor traversal and behavior when rows change while paging. Avoid raw SQL keys, secrets and authorization bypass through cursors. Stable sort order matters even when data has duplicate created timestamps: add a unique tie-breaker. For many datasets, a snapshot or keyset approach is necessary if strict consistency is required, and each choice has performance/retention tradeoffs that require measurement.

Specify fields `items`, `next_cursor`, `total` (only if accurate and justified), limit defaults and parameter validation. RFC 8288 defines web linking and `Link` response fields, but does not force any pagination query parameter name or JSON envelope. Include coverage for malformed/tampered cursor, oversized pages, another tenant using a cursor, end of results, changing filters, and result ordering under concurrent changes. [RFC 8288](https://www.rfc-editor.org/rfc/rfc8288.html); [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html).
