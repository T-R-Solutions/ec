# Problem Details and Error Response Contracts

RFC 9457 obsoletes RFC 7807. The JSON serialization media type is `application/problem+json`; define stable `type` URIs, `title`, optional `detail`, `instance`, and optional extension members as contractually needed. The response HTTP status remains the transport status; the `status` member is advisory and may not be present. A client MUST NOT parse localized `detail` to determine machine behavior; use `type` and defined extensions instead. Problem response must not disclose internal file paths, stack traces, secrets, ID existence or personally sensitive data. Authentication error semantics must match the actual security profile.

Per-endpoint table: invalid syntax, wrong content type, validation error, missing permissions, not found/hidden, concurrency loss, policy conflict, exhausted quota, service unavailable. Include negative tests that deliberately supply wrong `status` field, unknown extensions and absent optional fields. Decide retryability using status plus operation semantics, not a blanket “retry every 5xx”. The sample model includes a `status` member, but callers must not assume it is mandatory in every compliant RFC 9457 response. [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html).
