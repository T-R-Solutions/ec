# Browser, viewport, accessibility and user-path matrix

For each high-risk flow, select viewports and browser engines based on the deployment support contract. Chromium-only evidence must be described as Chromium-only; cross-browser validation requires real Firefox/WebKit executions. In responsive CI tools, check table/log overflow, deep links, keyboard-only DAG alternatives, focus after dialogs and screen-reader narration where the spec requires them.

Use role/name queries and keyboard checks for automation, but note they do not certify WCAG AA. Automated accessibility scanners only flag a subset of issues; human judgement and actual assistive-technology use remain necessary for accessibility evaluation and release acceptance. State locale/timezone, reduced-motion and text expansion test scope.
