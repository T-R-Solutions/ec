# OpenAPI, Schema Evolution and Description-vs-Implementation Gap

> Commands, fixture paths and historical execution claims from the source package are illustrative or imported evidence unless the corresponding files are present and independently checked; they are not current test results or bundled executable tools.

OpenAPI Specification 3.2.1 (2026-09-10) is the current published source reviewed for this skill. OAS describes HTTP APIs; a syntactically valid OAS description does not prove the provider follows it. This package includes an **OpenAPI 3.1.0** YAML example to maximize compatibility with locally available schema tooling. Verify exact tool support before using newer 3.2 features; do not call the example a complete OAS 3.2.1 conformance test. OAS itself may use YAML or JSON; the host product retains control over its **configuration file** format. On the wire, media types are separately negotiated.

Record operationId, methods, parameters, security schemes, request bodies, response statuses, media types, headers, examples and components. Test JSON Schema fields including `required`, nullable types, additionalProperties, enums and formats (format checking can be implementation-specific). Compare old/new interface descriptions, then run consumer contract tests against a real provider and report both static and runtime evidence. Reject changes that silently expand privileges or lower validation. [OpenAPI 3.2.1](https://spec.openapis.org/oas/v3.2.1.html); [OAS index](https://spec.openapis.org/oas/); [JSON Schema](https://json-schema.org/draft/2020-12).
