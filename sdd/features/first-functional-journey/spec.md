# Primeira jornada funcional

Estado: implementação incremental, sem aceite da jornada. Governança possui feature própria.

## Escopo e contrato v1alpha1

REQ-01: configuração canônica YAML de um projeto e um pipeline de uma etapa, sem DAG, triggers, herança ou plugins. `apiVersion: ec/v1alpha1`, `kind: ProjectPipeline`, `project`, `pipeline`, `repository`, `commit`, `script`, `timeoutSeconds`, `artifact`. Todos obrigatórios; nomes ASCII minúsculos/hífen até 64 caracteres, commit Git SHA-1 de 40 dígitos hexadecimais, repositório local absoluto controlado pelo operador, script até 8192 bytes, timeout decimal entre 1 e 3600 segundos (aspas aceitas; o schema define a interpretação numérica), artefato relativo sem traversal. Repositórios remotos e credenciais VCS ficam para próxima revisão de schema. O operador configura allowlist fora do YAML antes de habilitar execução. O schema sozinho não autoriza caminhos ou execução.

Parser aceita um documento UTF-8 até 64 KiB, profundidade até 16, até 4096 eventos e escalares até 8192 bytes. São limites conservadores iniciais, sem promessa de capacidade. Rejeitar chaves duplicadas antes de criar mapas, chaves complexas, aliases, anchors, tags, merge keys, campos desconhecidos, null e coleções nos campos escalares. Credenciais/sessões não possuem campos; segredos literais dentro de scripts arbitrários não são detectáveis genericamente: a política inicial proíbe fornecê-los. Suporte a referências de segredos e sua resolução ainda precisa ser implementado antes de aceitar jobs que precisem de credenciais. Comentários não fazem parte do modelo; editor deverá preservar texto original ou apresentar diff antes de reserializar.

REQ-02: revisão imutável identifica bytes YAML por SHA-256; configurações desejadas têm autoridade nos bytes versionados, projeções são reconstruíveis. Publicação recebe request ID, base revision e YAML; autenticação e autorização precedem efeitos. Na transação PostgreSQL: bloquear projeto, comparar base, inserir revisão imutável e projeção, atualizar publicada/efetiva e recibo. Neste recurso sem efeitos externos, publicada e efetiva podem avançar na mesma transação, com campos distintos. Antes de commit, queda reverte; depois de commit, repetir request ID retorna recibo idêntico ou rejeita payload diferente. Preferência futura por Git para configuração exige mecanismo de reconciliação separado; não há dupla gravação banco/Git neste primeiro fluxo proposto.

REQ-03: usuário possui identidade opaca, sessão expirada/revogada é rejeitada. Papéis iniciais viewer/operator/admin por projeto; viewer apenas lê. Agent possui identidade e credencial separadas, nunca sessão de usuário. Segredos por referências resolvidas fora do YAML, ainda pendentes. Server decide acesso por ação/recurso. Operação negada não grava revisão, fila, logs nem recibo de sucesso. HTTP `/api/v1`, erros JSON com code/message/requestId; 400 sintaxe, 401 sessão, 403 permissão, 404 recurso autorizado ausente, 409 conflito/fence/requestId, 422 regra ou referência, 413 limite. IDs fornecidos pelo cliente não autenticam.

REQ-04: execução fixa revisionId/configHash e commit SHA completo na submissão; edição posterior não os altera. Run: queued → assigned → running → succeeded/failed/timed_out/cancelled; cancel_requested é intenção persistida separada, exibida até confirmação. Attempt tem ID, ordinal, agentSessionId, fence crescente, leaseUntil e receipt. Capacidade inicial Linux com um slot anunciado. Agent registra e estabelece sessão autenticada; reinício cria sessão nova e invalida a anterior. Reserva bloqueia slot e job em uma transação PostgreSQL; nenhum slot pode possuir duas tentativas ativas. Heartbeat renova somente lease/fence/sessão vigentes. Lease vencido perde autoridade antes de reatribuição. Retry por perda de lease, máximo duas tentativas; falha de script não recebe retry automático. Podem repetir efeitos externos. Cancelamento e conclusão disputam o mesmo lock; cancelamento confirmado vence se solicitado primeiro; conclusão já commitada torna cancelamento sem efeito com resposta explícita. Resultado obsoleto é rejeitado. Replay do resultado aceito devolve recibo persistido; divergência no payload é conflito. Reconexão consulta tentativa e recibos antes de executar novamente.

REQ-05: workspace por tentativa; checkout verifica HEAD igual ao SHA fixado. Execução confiável local, sem isolamento alegado. Preparação falha antes de running; processo e descendentes recebem término no timeout/cancelamento, com causa distinta de exit code. stdout/stderr drenados independentemente; logs contêm run/attempt/step/stream/sequence, chunks até 64 KiB e total até 16 MiB por tentativa com truncamento explícito. Persistir chunk e ack juntos; replay igual é idempotente, divergente é conflito. Finalização inclui último sequence confirmado. Artefato até 16 MiB: staging, tamanho/hash esperados, finalização verifica bytes e publica identidade imutável em transação; incompleto/corrompido não aparece como íntegro. Downloads exigem acesso ao projeto. Retenção e controles para jobs não confiáveis permanecem planejados.

REQ-06: Vue 3/TypeScript/Pinia oferece projetos, configuração, execuções e agentes. Visual estruturado de uma etapa, formulário e YAML usam mesmo modelo; YAML inválido mantém último modelo válido e diagnóstico. Rascunho, validação local, pedido enviado, aceito, iniciado, finalizado e confirmado têm rótulos separados; frontend não infere confirmação pela ausência de erro. Teclado e foco, estados vazios/erro/acesso negado/desconectado devem ser exercitados no navegador com API real.

## Aceite

- AC-01 → REQ-01: parser/schema executáveis rejeitam duplicatas, construções proibidas, referências/campos inválidos e limites; round-trip sem perda de campos suportados.
- AC-02 → REQ-02: publicação real sobre PostgreSQL demonstra conflito, revisão imutável, repetição idempotente e reinício antes/depois do commit.
- AC-03 → REQ-03: API real autentica e rejeita acesso sem produzir efeitos; credenciais não entram no YAML.
- AC-04 → REQ-04: reservas concorrentes em PostgreSQL real, leases/fencing, replay, desconexão/reconexão, reinício e corrida cancelamento/conclusão demonstrados.
- AC-05 → REQ-05: Agent real executa checkout fixo, sucesso, nonzero, preparação falha, volume, timeout e cancelamento de descendentes; logs e artefatos reais com integridade e acesso.
- AC-06 → REQ-06: frontend real demonstra três modos equivalentes, teclado e estados de erro com Server/PostgreSQL/Agent reais.
- AC-07 → REQ-04: jornada integrada publica, submete e consulta resultado/artefato com revisões fixadas mesmo após alterações posteriores.
